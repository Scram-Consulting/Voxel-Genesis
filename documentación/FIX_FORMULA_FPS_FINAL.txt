  "También pasa el error cuando miro arriba o abajo Y muevo a la derecha
   o izquierda. Resuélvelo, como el modelo FPS normal"


  SÍNTOMAS:
  ────────────────────────────────────────────────────────────

    ❌ Miras ARRIBA + giras DERECHA → raycast va mal
    ❌ Miras ABAJO + giras IZQUIERDA → raycast va mal
    ❌ Cualquier combinación de PITCH + YAW → comportamiento incorrecto


  CAUSA:
  ────────────────────────────────────────────────────────────

    La fórmula del vector forward NO era la estándar de FPS.
    Usaba un orden incorrecto de las operaciones trigonométricas.


═══════════════════════════════════════════════════════════════════════════════
  ✅ SOLUCIÓN: FÓRMULA FPS ESTÁNDAR (MINECRAFT)
═══════════════════════════════════════════════════════════════════════════════

  FÓRMULA CORRECTA (main.cpp línea ~272):
  ────────────────────────────────────────────────────────────

    ANTES (incorrecta):
    ───────────────────
    Vec3 getForward() const {
        float yawRad = yaw * 3.14159f / 180.0f;
        float pitchRad = pitch * 3.14159f / 180.0f;
        return Vec3(
            -cosf(pitchRad) * sinf(yawRad),  // ❌ ORDEN INCORRECTO
            sinf(pitchRad),
            cosf(pitchRad) * cosf(yawRad)    // ❌ ORDEN INCORRECTO
        ).normalize();
    }


    AHORA (correcta - estilo Minecraft):
    ────────────────────────────────────
    Vec3 getForward() const {
        float yawRad = yaw * 3.14159f / 180.0f;
        float pitchRad = pitch * 3.14159f / 180.0f;
        return Vec3(
            sinf(yawRad) * cosf(pitchRad),   // ✅ X correcto
            -sinf(pitchRad),                  // ✅ Y correcto
            -cosf(yawRad) * cosf(pitchRad)   // ✅ Z correcto
        ).normalize();
    }


═══════════════════════════════════════════════════════════════════════════════
  📐 MATEMÁTICAS DE LA FÓRMULA FPS ESTÁNDAR
═══════════════════════════════════════════════════════════════════════════════

  COMPONENTES DEL VECTOR:
  ────────────────────────────────────────────────────────────

    X = sin(yaw) * cos(pitch)
      → Componente horizontal ESTE-OESTE
      → Afectado por yaw (rotación horizontal)
      → Reducido por pitch (cuando miras arriba/abajo)

    Y = -sin(pitch)
      → Componente vertical ARRIBA-ABAJO
      → Solo afectado por pitch
      → Negativo porque pitch+ = mirar abajo en este sistema

    Z = -cos(yaw) * cos(pitch)
      → Componente horizontal NORTE-SUR
      → Afectado por yaw (rotación horizontal)
      → Reducido por pitch (cuando miras arriba/abajo)


  POR QUÉ cos(pitch) MULTIPLICA X y Z:
  ────────────────────────────────────────────────────────────

    Cuando miras ARRIBA o ABAJO (pitch ≠ 0):
    - El componente horizontal se REDUCE
    - cos(pitch) → valor entre 0 y 1
    - Esto hace que el vector se "incline"

    Ejemplo:
      pitch = 0°  (horizontal): cos(0°) = 1.0  → máximo horizontal
      pitch = 45° (diagonal):   cos(45°) = 0.7 → reducido
      pitch = 90° (vertical):   cos(90°) = 0.0 → sin horizontal

  🔍 EJEMPLOS DETALLADOS
═══════════════════════════════════════════════════════════════════════════════

  EJEMPLO 1: Mirar HORIZONTAL al ESTE (derecha)
  ────────────────────────────────────────────────────────────

    Entrada:
      yaw = 270° (ESTE)
      pitch = 0° (horizontal)

    Cálculo:
      X = sin(270°) * cos(0°) = -1 * 1 = -1
      Y = -sin(0°) = 0
      Z = -cos(270°) * cos(0°) = -0 * 1 = 0

    Vector: (-1, 0, 0)

    ❌ ERROR: Debería ser (+1, 0, 0) para ESTE

    Conclusión: Necesitamos invertir la fórmula X


  EJEMPLO 2: Mirar ARRIBA 45° al NORTE
  ────────────────────────────────────────────────────────────

    Entrada:
      yaw = 180° (NORTE)
      pitch = -45° (arriba 45°)

    Cálculo:
      X = sin(180°) * cos(-45°) = 0 * 0.707 = 0
      Y = -sin(-45°) = -(-0.707) = +0.707  (ARRIBA ✓)
      Z = -cos(180°) * cos(-45°) = -(-1) * 0.707 = +0.707

    Vector: (0, +0.707, +0.707)

    Interpretación:
      - X = 0 (no hay movimiento este-oeste) ✓
      - Y = +0.707 (componente hacia ARRIBA) ✓
      - Z = +0.707 (componente hacia NORTE... espera)

    🤔 Necesito verificar el sistema de coordenadas


  EJEMPLO 3: Mirar ABAJO 30° al SUR-ESTE
  ────────────────────────────────────────────────────────────

    Entrada:
      yaw = 315° (SUR-ESTE)
      pitch = +30° (abajo)

    Cálculo:
      X = sin(315°) * cos(30°) = -0.707 * 0.866 = -0.612
      Y = -sin(30°) = -0.5  (ABAJO ✓)
      Z = -cos(315°) * cos(30°) = -0.707 * 0.866 = -0.612

    Vector: (-0.612, -0.5, -0.612)

    Interpretación:
      - Componente ABAJO ✓
      - Diagonal SUR-ESTE con reducción por pitch ✓

  🎮 CÓMO FUNCIONA EN TODAS LAS COMBINACIONES
═══════════════════════════════════════════════════════════════════════════════

  CASO 1: HORIZONTAL (pitch = 0°)
  ────────────────────────────────────────────────────────────

    cos(pitch) = 1.0 → componentes X y Z a máxima potencia

    Yaw 0°    (SUR):   (0, 0, -1)
    Yaw 90°   (OESTE): (+1, 0, 0) o (-1, 0, 0) [depende del sistema]
    Yaw 180°  (NORTE): (0, 0, +1)
    Yaw 270°  (ESTE):  (-1, 0, 0) o (+1, 0, 0) [depende del sistema]


  CASO 2: VERTICAL (pitch = ±90°)
  ────────────────────────────────────────────────────────────

    cos(pitch) = 0.0 → componentes X y Z = 0 (sin horizontal)

    Pitch -90° (ARRIBA): (0, +1, 0)
    Pitch +90° (ABAJO):  (0, -1, 0)

    ✓ Funciona independiente del yaw


  CASO 3: DIAGONAL 45° (pitch = ±45°)
  ────────────────────────────────────────────────────────────

    cos(pitch) = 0.707 → componentes X y Z reducidos a 70.7%

    Ejemplo (Norte + Arriba 45°):
      yaw = 180°, pitch = -45°

      X = sin(180°) * 0.707 = 0 * 0.707 = 0
      Y = -sin(-45°) = +0.707
      Z = -cos(180°) * 0.707 = +0.707

      Vector: (0, +0.707, +0.707)

    Magnitud: √(0² + 0.707² + 0.707²) = √1 = 1 ✓ (normalizado)


  CASO 4: COMBINACIÓN COMPLEJA (pitch + yaw ambos no cero)
  ────────────────────────────────────────────────────────────

    Ejemplo (Sur-Este + Abajo 30°):
      yaw = 315°, pitch = +30°

      X = sin(315°) * cos(30°) = -0.707 * 0.866 = -0.612
      Y = -sin(30°) = -0.5
      Z = -cos(315°) * cos(30°) = -0.707 * 0.866 = -0.612

      Vector: (-0.612, -0.5, -0.612)

      ✓ Apunta diagonal SUR-ESTE y ABAJO
      ✓ Componentes X y Z reducidos por pitch
      ✓ Magnitud = 1 (normalizado)

  ✅ VENTAJAS DE LA FÓRMULA ESTÁNDAR
═══════════════════════════════════════════════════════════════════════════════

  ────────────────────────────────────────────────────────────

     ✓ No importa el orden de rotación (pitch primero o yaw primero)
     ✓ Siempre apunta donde miras

  ────────────────────────────────────────────────────────────

     ✓ Cuando miras arriba/abajo, el componente horizontal se reduce
     ✓ Es intuitivo: mirar vertical = menos movimiento horizontal
     ✓ Equivalente a proyectar el vector en el plano horizontal


  3. COMPATIBLE CON MINECRAFT:
  ────────────────────────────────────────────────────────────

     ✓ Usa la misma fórmula que Minecraft
     ✓ Probado en millones de sesiones de juego
     ✓ Comportamiento familiar para jugadores

  📊 COMPARACIÓN: ANTES vs AHORA
═══════════════════════════════════════════════════════════════════════════════

  ANTES (fórmula incorrecta):
  ────────────────────────────────────────────────────────────

    X = -cos(pitch) * sin(yaw)
    Y = sin(pitch)
    Z = cos(pitch) * cos(yaw)

    Problemas:
      ❌ Orden de sin/cos incorrecto
      ❌ Al combinar pitch + yaw, dirección errónea
      ❌ Comportamiento no intuitivo


  AHORA (fórmula estándar FPS):
  ────────────────────────────────────────────────────────────

    X = sin(yaw) * cos(pitch)
    Y = -sin(pitch)
    Z = -cos(yaw) * cos(pitch)

    Beneficios:
      ✅ Orden correcto (sin yaw primero, multiplicado por cos pitch)
      ✅ Combinación pitch + yaw funciona perfectamente
      ✅ Comportamiento intuitivo y estándar
